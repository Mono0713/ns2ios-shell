# 需要抓取一次的两个游戏

打包器做的每件事都从游戏自己的文件出发。只有两个游戏是例外，这一页专门讲它们。

| 游戏 | Title ID | 着色器数 | 代价 |
|---|---|---|---|
| **超级马里奥银河**（1.3.1） | `010099C022B96000` | 3,089 | 跑一次游戏，约一分钟 |
| **超级马里奥银河 2**（1.4.0） | `0100FD8022DAA000` | 3,797 | 一样，但它和一代只重叠 38.5% |

## 为什么这两作特殊

着色器必须在游戏跑起来之前就存在，要么作为文件，要么作为我们能重算出来的东西。三种情况，前两种是常态：

| 着色器在哪 | 例子 | 打包器怎么办 |
|---|---|---|
| 在游戏文件里，已经编好 | NVN 游戏（支持列表里 47 款）、哈迪斯（RomFS 里 74 个 SPIR-V） | 读出来、翻译 |
| 引擎自带**可读**的生成器 | 小丑牌的 LÖVE（`resources/shaders/*.fs` + `wrap_GraphicsShader.lua`） | **跑那个生成器**，产出游戏要编译的那份着色器 |
| 引擎从硬件状态生成，代码是编译过的 | **银河 1、2**（Hagi 把 GameCube/Wii 的 GX 管线状态变成 SPIR-V） | **没有东西可读——着色器只在游戏运行时存在** |

银河的着色器不是文件里的程序，而是一套 GX 管线配置*变成*的样子，由 Hagi（一个 C++ 写的着色器编译器，编译成机器码）从 `pipelineDB.pip` 算出来。要在 PC 上产出它们，等于重写那个编译器（GX 状态 → SPIR-V 的翻译器）——那是另一个项目，不是漏掉的步骤。而抓一次只要一分钟。

## 怎么做

第一步打出来的包**能启动、有声音、但没有画面**。这正是目的：让它跑到能自己生成着色器的那一步。

### 1. 打一个不带着色器的包

```bash
python scripts/nxn_pack.py <shell.zip> <游戏文件夹> -k prod.keys --tools <工具文件夹> --no-shaders -o Galaxy-capture.ipa
```

### 2. 告诉应用往哪写

装好 IPA 后：

1. 在「文件」App 里，`Documents/log.txt` 所在那一层，新建一个空文件夹 `vkcap`。
2. 在 `Documents/env.txt` 里加一行（没有就新建，一行一个 `KEY=VALUE`）：

```
DM_VK_CAPTURE=vkcap
```

路径是相对应用 Documents 的，也就是 `log.txt` 所在的那一层——不用去查沙盒路径。

### 3. 跑一次游戏

启动后放一分钟。它会显示标题画面并开始创建管线，每创建一个着色器就往 `vkcap/` 写一个 `<key>.spv`。看着像坏了（黑屏、也许有个 logo）是正常的，因为什么都没画。

退出后看那个文件夹。**银河 1 应该有 3,089 个文件，银河 2 是 3,797 个。** 少了就再跑一次：已经抓到的文件会被跳过，重复跑是安全的，后面关卡的场景还会补上更多。

### 4. 重新打包

```bash
python scripts/nxn_pack.py <shell.zip> <游戏文件夹> -k prod.keys --tools <工具文件夹> --vk-capture "抓取文件夹的路径" -o Galaxy.ipa
```

3,089 个模块会变成约 3,950 份 Metal 源码（部分片元着色器还要为双源混合多出一个变体）。手机上首次启动会全部编译一遍——几分钟，有进度页——之后就走系统的着色器缓存。

## 几点说明

- **抓取是按游戏算的，不是按版本。** 换了存档或更新包不影响它；换成另一个游戏才要重新抓。
- **留着那个文件夹。** 以后重打同一个游戏只需要 `--vk-capture`，不用再跑一次。
- **带着色器的 IPA 里是你的游戏文件。** 和这个打包器产出的所有包一样，仅供自己使用。
- 如果你打的游戏**不是**这两作却报 `no SPIR-V files in .../RomFS`，那是 bug——请附上 `Documents/log.txt` 开个 issue。
